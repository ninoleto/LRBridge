Other inspected SDK contracts:

- `getSelectedSpotType()` returns `heal_patchmatch`, `heal` or `clone` and a generative-AI boolean valid only for `heal_patchmatch`.
- `setSelectedSpotType(spotType, useGenAI)` accepts those types and a boolean to enable generative AI when selecting `heal_patchmatch`. This changes the existing repair, unlike `newSpotType`. Both type APIs require Develop and open Remove, and date from SDK 14.1. Fill calls this setter with exactly two arguments and uses the getter for confirmation.
- `getSelectedSpotIndex(whichFeature)` returns an index or nil. `setSelectedSpotIndex(spotIndex, whichFeature)` takes a numeric index and optional feature, returning true or false plus an error string. The same two feature values/default apply. Both require Develop and open Remove.
- `getAllSpots(whichFeature)` returns a list; `countAllSpots(whichFeature)` returns a number. Both require Develop. Selection/inventory APIs were introduced in 14.1 and updated for feature selection in 14.5. The returned spot-table fields are not documented as an identity/parameter schema.

`remove.repair.action` uses original photo/module/context/Develop/epoch/revision guards and a selected-repair token. The token combines the documented selected index with bounded opaque native inventory/parameter/type equality evidence; no undocumented ID field is invented. A selected index that cannot be matched to the native list disables actions. The selected index, inventory, params and type are read again after yielding validation and immediately before execution. Native selection changes invalidate obsolete actions. Original target token is required in both admission and result handling. Delete uses a dedicated removal-proof flag, count change and remaining-inventory comparison. Missing/forged target proof, wrong-record deletion, SDK errors or stale contexts cannot report confirmed removal. Shared Undo/Redo stays global; no preference or tool-navigation history entries are manufactured.

`remove.repair.fill.set` uses the same original repair token in admission, command and result. The SDK worker revalidates photo/tool/mode and full selected identity after its yielding validation, then calls the dedicated setter. Confirmation requires native type/GenAI, the original selected index/count, preservation of every other repair and all new-stroke preferences, and dedicated edit proof. A stale/nil/unavailable selection never enables a cached target. The dropdown follows native changes, retains its requested choice while waiting and keeps shared history/focus/page position intact. No automatic selection recovery or mode forcing occurs during feedback.

`remove.repair.param.set` binds the original photo/mode/repair token and revalidates immediately before the documented one-argument `setSelectedSpotParams(spotParams)`. It deep-copies the entire fresh native parameter table and changes only the requested root `Opacity` or `Feather`, preserving all other fields because partial-update semantics are undocumented. Raw native 0..1 values are retained internally; the percent editor displays/commits 0..100 with step 1. An untouched rounded display never writes. Confirmation requires actual raw value, same selected index/type, unchanged other selected parameters, every other repair and brush preferences. Missing/non-numeric/out-of-range native fields disable editing. A conservative preservation failure is reported, not guessed successful. The user reports initial successful live use; detailed setter behavior and availability across every repair type remain unverified.

Slider requests serialize and coalesce using the established displayed/confirmed/requested lifecycle. Only the exact SDK result, including its confirmed successor token, can advance queued edits across that operation's identity change. An earlier result cannot rebind a newer repair even when its parameter value happens to match. Native selection/unavailable readback cancels pending gestures/drafts; HTTP acknowledgement is not confirmation. Shared history remains native, without fabricated entries.
