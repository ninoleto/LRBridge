## Controlled-retest notes

- The authoritative `select_all` result is **PASS**. The initial attempt occurred before the development plugin was reloaded, while Lightroom had cached the old Lua modules.
- The authoritative results for the original nine Lightroom 15.3 no-ops are the controlled re-tests shown above: eight now **PASS**, while `application.action / cycle_loupe_info` remains **FAIL**.
- The authoritative `toggle_secondary_fullscreen` result is **PASS**. The controlled test confirmed that it changed the Secondary Display from fullscreen to windowed.
- The authoritative `resetAllDevelopAdjustments` result is **PASS**. Lightroom was completely restarted, and fresh `AutoStartPolling` initialization occurred after the updated `Driver.lua` modification time. Exactly one command was admitted; the queue transitioned `0 → 1 → 0`; enqueue and dequeue deltas were both 1; heartbeat and polling remained active; Lightroom remained in Develop; and the active photo visibly reset Exposure, Contrast, White Balance, crop, and all other Develop adjustments.
- The earlier apparent `resetAllDevelopAdjustments` failure was **INCONCLUSIVE**, not a command failure. Lightroom was still running a cached `Driver.lua` loaded before the action existed. Unknown actions can currently be dequeued and return `false` silently without producing a result payload. A complete Lightroom restart is required after Lua plug-in source changes before controlled runtime testing.
- Lightroom was completely restarted after `Commands.lua`, `Selection.lua`, and `Photo.lua` changed. Fresh `AutoStartPolling: silent polling started` and `AutoStartPolling: polling loop started` entries occurred after all three file modification times before testing the four new operations.
- Each `photo.rotate` and `selection.extend` test admitted exactly one valid command, observed queue completion `0 → 1 → 0`, recorded enqueue and dequeue deltas of 1, and retained advancing heartbeat and active polling.
- `photo.rotate / left` visibly rotated the active photo 90 degrees counter-clockwise; `photo.rotate / right` visibly rotated it 90 degrees clockwise.
- `selection.extend / right / amount=1` added exactly one adjacent photo to the right while retaining the original selection; `selection.extend / left / amount=1` did the same to the left.
- The shared `Parser.lua` transport defect was fixed so string `value` and `scope` fields reach Lua dispatch. Lightroom was completely restarted afterward, and fresh `AutoStartPolling` initialization was proven after the updated Lua modification times.
- Each `photo.treatment` and `photo.reveal` test completed queue `0 → 1 → 0`; enqueue and dequeue deltas were exactly 1; heartbeat continued; and no execution errors occurred. The active photo visibly changed to Black & White, visibly returned to Color, and was visibly revealed and selected in Explorer.
- Before the first rotation test, a request using `/api/command` was mistakenly sent to backend port 17891. It returned HTTP 404 and was never admitted or enqueued, so it was a routing mistake rather than a Lightroom command failure. In the development setup, `/api/command` is exposed by the Web Controller proxy on port 17892; direct backend command routes are on port 17891.

- All eight fixed crop-aspect modes and Custom Crop were manually verified from the Web Controller: `original`, `asshot`, `1x1`, `2x3`, `4x5`, `5x7`, `16x9`, `16x10`, and `custom / w=16 / h=10`.

- Original Aspect uses the photo's original aspect ratio and changes only the aspect ratio. Reset Crop remains separate and resets the complete crop state.
- The fixed 2:3 preset visibly matched Original on the tested native 3:2 photo. Matching Original in that case is expected and is not a command failure.
- Camera Crop uses Lightroom's As Shot option and visibly matched Original because the tested photo had no distinct camera-recorded crop. Matching Original in that case is not a command failure.
- Fixed 16:10 passed visibly and uses the exact SDK table `{ w = 16, h = 10 }`.
- Custom Crop passed visibly with exact validated Width and Height values preserved through HTTP extraction, queue JSON, Lua parsing and dispatch, and the SDK table call.
- The LRBridge Custom Crop modal worked as designed. It is LRBridge's own modal, not Lightroom's native Enter Custom dialog.
