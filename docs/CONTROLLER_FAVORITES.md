# Controller favorites and compact Selection layout

Development checkpoint authorized 2026-09-18. The user likes the expanded chooser and Selection layout. Final Quick Copy wording/feedback has automated fixture evidence; native Copy/Paste acceptance is still outstanding. This development checkpoint does not authorize a push, tag or release.

## Using the bar

The persistent bar defaults to **Undo | Redo**, with **Customize** at its right. Customize offers **71 existing actions**: History, every action button in Selection, and every action button in Application. New choices are never added automatically. Search filters by action name, tab or section; choices are grouped by their original sections and exclude already-added actions. Labels such as **Next Photo**, **Rate 5 Stars**, **Switch to Library** and **Secondary Display: Grid** make sense away from the source tab. Reordering uses accessible Move up/Move down buttons; no dragging is required. Restore defaults returns to Undo/Redo. An empty favorites list is allowed; Customize remains available.

| Source | Included sections | Actions |
| --- | --- | ---: |
| History | Undo, Redo | 2 |
| Selection | Navigate, Extend Selection, Photo, Flags, Rating, Adjust Rating, Color Label, Selection Operations | 31 |
| Selection | Export, Copy / Paste Settings | 4 |
| Application | Modules, Library Views, Develop Views, Zoom, Screen, Secondary Display | 34 |

All 17 sections are represented; **no existing action button from either tab is excluded**. This does not introduce commands that exist only in the HTTP API or SDK.

Arrangement is saved with the controller's existing browser-local preference approach, under `lrbridge.controller.favorites.v1`. Existing IDs, favorites and their order are preserved. It belongs to this browser profile and controller origin (address/port), not the Lightroom catalog or project configuration. Duplicates and unsupported IDs are filtered; corrupt storage falls back to defaults. If browser storage is blocked, the arrangement works until reload and Customize explains the limitation. No preference is sent to the server or committed.

The copy action is labeled **Quick Copy Settings** in Selection, the chooser and pinned favorites. Its tooltip/help says **“Copies settings from the active photo without opening a dialog. Uses the categories last selected in Lightroom’s Copy Settings dialog.”** The `clipboard.copy` ID and native SDK behavior are unchanged; existing saved favorites acquire the label without migration.

The bar stays one 64px row, with 44px minimum targets. Extra favorites scroll horizontally on narrow screens; labels and controls do not wrap into a tall panel. A ResizeObserver shares the actual rendered height with sticky navigation. Default Undo/Redo retain their action names during cooldown; availability comes from the original history state/gesture/cooldown guards. Toolbar elements persist across tabs and feedback. Focusable `aria-disabled` buttons reject activation through the original guard. No negative margins or reserved feedback area are used to compress the layout.

## Actions, results and review

Undo/Redo use the same guarded history function. Copy/Paste and Export share the very same action functions as Selection, retaining their complete-selection bindings, consumed request IDs and explicit uncertainty review. The 65 other Selection/Application actions use one descriptor and guarded handler for both originals and favorites, forwarding to the existing `sendCommand(commandPath(item))` route. No hidden button is invoked or source tab mounted to dispatch. Their existing native scope is unchanged: Photo actions use the active photo, and Selection commands retain Lightroom's current selection/view semantics. They do not acquire Copy/Paste's captured-selection protocol merely by becoming favorites. No HTTP/SDK mutation path, confirmation, request ID, automatic retry, selection rewrite or optimistic Lightroom state is introduced.

Shared original/favorite availability uses the existing heartbeat, authoritative active photo/module and history/gesture/tool interlocks. Photo-dependent actions are disabled without an active photo; First/Last Photo, Select All and Invert Selection remain usable without one. Library and Develop views follow their existing section context; zoom requires Library or Develop with an active photo. Global module/screen/display actions remain available without a photo, except Fullscreen Preview. A shared in-flight guard blocks duplicate/concurrent generic action submission and interlocks history/clipboard operations until HTTP settlement. HTTP admission means **requested**, not native completion; a transport failure is unconfirmed and never automatically retried.

The current module is highlighted from authoritative context in both originals and favorites. Existing view, zoom, display, flag and rating commands have no corresponding polled state here; their buttons remain momentary and do not invent active/toggle feedback. Secondary-view invocation retains its native repeat-view behavior. The installed SDK's `LrApplicationView`/`LrSelection` reference and the unchanged plug-in handlers remain the source of native behavior; this is a browser integration, not expanded SDK capability or new telemetry.

Routine feedback is plain text in a discreet fixed notice at the bottom right, outside the favorites bar: for example, **“Zoom In — command sent.”** It identifies the action and reports submission, never confirmed Lightroom completion. It has no action button, takes no layout space and does not intercept pointer input. The sent acknowledgement disappears after four seconds; polling cannot renew it or bring it back. Pending requests show an action-specific waiting message until feedback changes. Neither appearance nor expiry moves toolbar controls, keyboard focus, page scrolling or horizontal favorites scrolling. Detailed feedback remains in its original controller area.

Errors and uncertain results do not expire. An error retains **Details** access across tabs, other favorite actions and removal of its favorite, until recovery or explicit **Dismiss**. Dismiss only hides that browser notice; it never retries, modifies Lightroom state or acknowledges a protected operation. Captured generic-command error details remain readable even after later commands update the general status. A notice temporarily hides while its original details have focus, so it cannot cover that text/control; it returns when focus moves away if unresolved.

Any uncertain Copy/Paste or Export request offers **Review**, including on other tabs and after its favorite was removed. It has no Dismiss control. Review navigates to Selection and focuses the original acknowledgement; it does not itself acknowledge or execute anything. Only that existing workflow resolves the review requirement. Required review takes priority over other errors and routine messages; additional errors/reviews remain accessible after the first is resolved. Native receipt ownership, guards, acknowledgement and duplicate/retry protections are unchanged.

Selection starts with **Navigate**. Extend Selection, Photo, Flags, Rating, Adjust Rating, Color Label and Selection Operations retain their relative order, followed by Export and finally **Copy / Paste Settings**. The entire Copy/Paste section moves together: its two buttons, three help paragraphs, progress/results and required review controls. There is no destination-count line or technical Details panel. Results appear directly and explain unconfirmed batch coverage or pending/unknown AI processing. Favorites feedback still opens the section and focuses its result or required acknowledgement. No empty result area takes space. Adding these actions to favorites never moves those explanations into the global bar. The former global clipboard block and two-row toolbar are removed. Section scroll margins account for the measured sticky bar height.

Export retains its Selection controls and Previous warning (last Lightroom export settings, possibly immediate start). The Previous favorite also has an accessible description/title and the warning in Customize. Selecting an Export favorite keeps its existing bounded read-only selection polling active across tabs; removing all Export favorites restores the original inactive polling behavior unless an operation is still pending. Queue/SDK behavior and accepted Export observation limits remain unchanged.

## Verification and loading

Isolated Chromium fixtures render the actual production controller with mock Lightroom data. Focused checks cover desktop/phone geometry (1280, 768, 390 and 320), no global clipboard gap, toolbar/navigation alignment, touch targets, customization add/remove/order/defaults, browser reload persistence and blocked storage, keyboard Escape/focus, tab persistence, original action availability, duplicate requests, review access and focus/page/horizontal-scroll stability. The expanded checks enumerate every original action, verify grouped search/no-match/duplicate handling and saved order, exercise representative actions from both tabs across all seven controller tabs, and verify photo/module/connection/gesture guards, authoritative module state, shared original/favorite dispatch, reordered Selection and heading visibility. The focused descriptor check dispatches all 65 added choices to a fake sender. Capture artifacts show the actual rendered controller; they are not design mockups or screenshots of Lightroom.

The favorites browser check retains Copy/Paste, Export and Undo/Redo dispatch/availability/uncertainty coverage. Shared-history and changed JavaScript/inline-controller syntax checks provide supporting coverage. The prior standalone Copy/Paste/Export browser checks and 61 Copy/Paste / 42 Export HTTP/queue/production-Lua mock-SDK scenarios remain prior evidence for those unchanged implementations; they are not rerun for this browser-only expansion. No unrelated or full-suite rerun is required; the prior history-only fixture's missing People endpoint remains outside this change.

Final feedback checks verify the exact copy label/help in all three locations, saved-ID persistence, the longer Selection label at desktop/phone widths, action-specific plain-text acknowledgements, four-second expiry without geometry/focus/scroll changes, no resurrection through polling, persistent injected HTTP failure through another success/removal/tab change, preserved error details, explicit notice dismissal and non-expiring native uncertainty review through the original acknowledgement. All requests use isolated fixtures, including the deliberately injected HTTP 503; no real clipboard, photo or export is changed.

To load these refinements from the already-loaded compact design, **refresh the controller (Ctrl+R)**. There is no new server route or Lua change, so no LRBridge restart or Lightroom reload is needed. The earlier native Copy/Paste implementation still needs its initial plug-in reload if it has not been loaded yet; do that only before native disposable-photo testing, not for this layout review. No automated check changes the user's photos, native clipboard or export files.
